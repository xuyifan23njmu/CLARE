# CLARE

## A Dual-Module Framework for Assessing Quality and Fairness in LLM-Generated Clinical EMRs

CLARE is a research framework for evaluating the quality and demographic representation of synthetic electronic medical records (EMRs) generated by large language models (LLMs). It provides complementary assessments to help model developers and synthetic-data researchers compare generated clinical notes and identify potential issues before secondary use. Its demographic analyses can also support the review of synthetic teaching cases.

This repository contains research scripts and prompt resources associated with the CLARE study. The current public release includes generation workflows and selected demographic and text-length analyses; it is not yet a complete, end-to-end reproduction package for every analysis in the manuscript.

## Framework overview

CLARE combines two complementary assessment perspectives:

- **Quality assessment:** examines the completeness of requested information and medical terminology in generated records. In the study, TSC focuses on the completeness of age and sex information, while MTA provides a terminology-based assessment.
- **Demographic-representation assessment:** compares age-group and sex distributions in synthetic records with reference distributions, using distributional comparisons and statistical analyses.

These perspectives are interpreted together rather than combined into a single composite score. A record set can contain complete demographic fields while still exhibiting substantial demographic imbalance. Likewise, agreement with reference demographics alone does not establish clinical validity.

In this study, fairness refers specifically to **demographic representation**. It should be distinguished from error-rate fairness, outcome fairness, or evidence of suitability for patient-level clinical decisions.

## Study setting

The manuscript investigates English and Chinese synthetic records for three diabetes categories:

- Gestational diabetes mellitus (GDM)
- Type 1 diabetes mellitus (T1DM)
- Type 2 diabetes mellitus (T2DM)

The study design comprises 12 models, 10 prompt templates, two languages, and three disease categories. Each disease- and language-specific instantiated prompt is used for 100 generation runs, giving a nominal total of 72,000 records. Repeated generations use the same instantiated prompt; they are not separate repetitions of the entire experiment. Actual output counts should be checked after generation because requests can fail or return unusable outputs.

The demographic reference statistics were supplied as aggregate data from Jiangsu, China. Patient-level reference records are not included in this repository.

## Getting started

### 1. Obtain the code

```bash
git clone https://github.com/xuyifan23njmu/CLARE.git
cd CLARE
```

### 2. Prepare an environment

Use an isolated Python environment. Dependencies vary by script:

| Workflow | Relevant dependencies |
| --- | --- |
| Spreadsheet processing and demographic summaries | pandas, openpyxl, NumPy |
| Statistical comparisons | SciPy |
| Generation workflows | requests, LangChain, langchain-community, langchain-experimental, Pydantic, retry |
| Ollama generation utilities | Ollama service and the selected model; pytz and tqdm |
| Notebook analyses | Jupyter and the packages imported by the selected notebook |

A version-pinned environment is not currently provided. Generation scripts use historical LangChain interfaces, so compatibility with newly released package versions should be checked before running experiments. The dependency list above describes the visible workflows rather than a tested installation specification.

### 3. Configure the selected workflow

Before executing a script:

1. Replace machine-specific input and output paths with local paths.
2. Check the required workbook names, sheet names, and column names.
3. Set the model identifier and, where applicable, API endpoint and generation parameters.
4. Configure credentials securely, preferably by adapting the script to read environment variables. Do not commit credentials or private datasets.
